# NoteKori

Turn a photo of a classroom whiteboard into an interactive study workspace: structured
notes, an easy Bangla explanation, corrected code, an animated mind map, flashcards,
a quiz, highlights, and Markdown / PDF export.

Handles Bangla, English, and mixed handwriting, plus code, pseudocode and diagrams.

---

## Quick start

Two terminals.

**Backend**

```bash
cd backend
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env               # then paste your API key into .env

uvicorn app.main:app --reload --port 8000
```

**Frontend**

```bash
cd frontend
npm install
npm run dev
```

| What | Where |
| --- | --- |
| App | http://localhost:3000 |
| API | http://localhost:8000 |
| API docs | http://localhost:8000/docs |

The header shows a live backend status dot, so you will know immediately if the API
key is missing or the backend is down.

## Getting an API key

NoteKori talks to the **Google AI Studio (Gemini) API**, which serves the vision-capable
Gemma models.

1. Get a free key at <https://aistudio.google.com/apikey>.
2. Put it in `backend/.env`:

```env
GEMMA_API_KEY=your_key_here
GEMMA_API_BASE_URL=https://generativelanguage.googleapis.com/v1beta
GEMMA_MODEL=gemma-3-27b-it
```

The key is read **only** by the backend. It is never sent to the browser.

### Choosing a model

`GEMMA_MODEL` is free-form, so you can swap models without touching code:

| Model | Notes |
| --- | --- |
| `gemma-3-27b-it` | Default. Open-weights, vision-capable, strong multilingual reading. |
| `gemma-3-12b-it` | Faster and cheaper, slightly weaker on messy handwriting. |
| `gemini-2.0-flash` | Fastest, and supports native JSON mode (see below). |

The backend detects Gemma models automatically and omits `responseMimeType`, because
Gemma on the Gemini API rejects JSON mode and system instructions. Gemini models get
strict JSON mode enabled.

> The original plan specified `gemma-4-26b-a4b-it`. That model ID could not be verified
> against any provider, so the default is the current vision-capable Gemma release.
> If your provider does expose that exact ID, just set `GEMMA_MODEL` to it.

## How it works

```
Upload image
      ↓
FastAPI validates type and size
      ↓
Pillow: EXIF rotate, downscale, gentle contrast and sharpening
      ↓
Gemma vision call with a strict JSON schema prompt
      ↓
Tolerant JSON recovery, then Pydantic validation
      ↓
Next.js renders the workspace
      ↓
Guide · Mind map · Flashcards · Quiz · Highlights · Export
```

### Surviving imperfect model output

A demo dies when the model returns *almost* valid JSON. The parser
(`backend/app/utils/json_parser.py`) recovers from every failure mode observed in
practice, in cheapest-repair-first order:

- markdown code fences
- explanatory prose before and after the object
- trailing commas
- raw newlines and tabs inside string values
- responses truncated mid-object by the token limit

If all of that fails, the backend makes **one** repair round-trip asking the model to
fix its own JSON. Beyond that it returns a clear error rather than a blank screen.

On top of that, `AnalysisResult` defaults every field, so a partial response still
renders a usable workspace, and mind map edges pointing at non-existent nodes are
pruned before they reach the graph renderer (which would otherwise throw).

## API

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/v1/health` | Status, active model, whether a key is configured |
| `POST` | `/api/v1/analyze` | `multipart/form-data` with `image` → analysis JSON |
| `POST` | `/api/v1/export/markdown` | Result + highlights → downloadable `.md` |

PDF export is handled in the browser via the print stylesheet — see below.

---

## Export

**Markdown** is generated by the backend: a single `.md` containing the study guide,
Bangla explanation, key concepts, corrected code, uncertain content, a Mermaid version
of the mind map, flashcards, quiz with answers, exam questions, the revision summary,
and your highlights. It drops straight into Obsidian.

**PDF** uses the browser's print-to-PDF against a dedicated print layout
(`components/export/PrintableReport.tsx`), rather than server-side WeasyPrint. This was
a deliberate change from the original plan:

- WeasyPrint needs system libraries (pango, cairo, gdk-pixbuf) plus a bundled Bangla
  font, which is a significant setup risk.
- Bangla conjuncts (juktakkhor) render correctly through the system font stack.
- Zero extra backend dependencies, and it works anywhere the app runs.

The entire interactive shell is marked `no-print`, so only the report reaches the page.

## Notes on the stack

- **npm, not Yarn.** Yarn was not installed and could not be added without root. Every
  command above uses npm; switch to Yarn freely if you prefer.
- **No OpenCV.** Preprocessing is Pillow-only and deliberately gentle. Aggressive
  denoising and binarisation destroy faint chalk and pencil strokes, costing more
  accuracy than they gain, and OpenCV added ~100 MB for no MVP benefit.
- **Mind map** uses `react-force-graph-2d` behind a `dynamic(..., { ssr: false })`
  import, because it touches `window` at module scope.
- **Session state** persists to localStorage, with an automatic in-memory fallback when
  storage is blocked (private browsing), so the app never gets stuck before hydration.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| Header shows "GEMMA_API_KEY not set" | Add the key to `backend/.env` and restart uvicorn. |
| "Backend offline" | uvicorn is not running, or `NEXT_PUBLIC_API_BASE_URL` is wrong. |
| 400 from the provider | `GEMMA_MODEL` does not exist or lacks vision support. |
| Bangla renders as boxes | Install a Bengali font (`noto-fonts` on most distros). |
